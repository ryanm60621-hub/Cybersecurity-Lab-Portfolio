# Incident Response Scenario

## Overview
This project documents an incident response exercise involving a compromised system and suspected data exfiltration. The exercise followed the main phases of incident handling from preparation through post-incident improvement.

## Scenario Analysis
- Identified unauthorized data exfiltration as a security incident.
- Looked for warning signs such as unusual outbound traffic, malware alerts, encrypted file transfers, and suspicious system behavior.
- Prioritized containment by isolating the affected system and blocking outbound traffic.
- Identified useful evidence sources including system logs, network logs, IDS alerts, and forensic images.
- Considered post-incident improvements such as patching, stronger controls, better logging, and improved monitoring.

## Tools and Concepts
- Incident detection and analysis
- Containment, eradication, and recovery
- Log and evidence collection
- IDS/IPS, SIEM, EDR, firewalls, and forensic tools

## What I Learned
Incident response works best when detection, containment, evidence collection, and recovery are planned before an incident happens. Good logging and monitoring can also shorten the time it takes to recognize unusual activity.

## Scope
This was an academic incident response scenario. It did not involve a real-world breach.
